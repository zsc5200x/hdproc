# AG Matrix (HDZZ) 项目结构分析

> 本文档详细说明项目各目录和文件的作用，帮助开发者快速理解整个系统架构。

## 📋 项目概述

**AG Matrix (HDZZ)** 是一个自动化体育博彩跟单系统，主要功能包括：
- 监听后台账号的实时注单
- 通过会员端账号自动跟单下注
- 提供 Web 界面管理和监控
- 支持 Telegram 机器人通知和控制

**技术栈**：Python 3.9+ / Playwright / HTTP API / WebUI (原生 JS)

**代码规模**：约 29,000 行 Python 代码

---

## 📁 顶层目录结构

```
hdzz/
├── app/              # 主应用目录（运行时工作目录）
├── src/              # 重构后的新代码（模块化架构）
├── data/             # 运行时数据存储

├── scripts/          # 启动脚本（macOS/Windows）
├── python/           # 便携式 Python 环境（打包用）
├── ms-playwright/    # 便携式 Playwright 浏览器（打包用）
└── _work/            # 临时工作目录
```

## 🎯 核心目录详解

### 1️⃣ `app/` - 主应用目录

这是整个系统的**运行时核心目录**，包含所有可执行的 Python 脚本和配置文件。

#### 📌 核心启动文件

| 文件 | 作用 | 说明 |
|------|------|------|
| `app.py` | **统一启动器** | 一键启动所有服务（监听、WebUI、会员续期、跟单引擎），管理进程生命周期 |
| `config.json` | **全局配置文件** | 存储后台账号信息、Telegram 配置、代理设置等 |
| `portable_env.py` | **环境适配模块** | 处理便携式打包环境的路径配置（Playwright 浏览器路径等） |

#### 📌 核心功能模块（Legacy 版本）

这些是**原始的单文件实现**，功能完整但代码较长（每个文件 5,000-90,000 行）：

| 文件 | 功能 | 核心职责 |
|------|------|----------|
| `ag_wmc_watch_legacy.py` | **后台注单监听器** | 轮询后台 `transform.php` 接口，抓取新注单并保存到 `orders/` 目录 |
| `follow_engine_legacy.py` | **跟单执行引擎** | 读取新注单，根据跟单规则自动调用会员端 API 下注 |
| `member_arsenal_watch_legacy.py` | **会员账号守护进程** | 自动登录会员端账号，维持会话有效性（自动刷新 cookie/uid） |
| `webui_server_legacy.py` | **Web 管理界面服务器** | 提供 HTTP 服务，展示注单、管理账号、配置跟单规则 |
| `telegram_bot_legacy.py` | **Telegram 机器人** | 通过 Telegram 接收命令、推送通知、远程控制系统 |
| `settlement_importer_legacy.py` | **结算数据导入器** | 从后台抓取历史结算数据，用于统计分析 |

#### 📌 核心功能模块（新版本 - Wrapper）

这些是**重构后的轻量级入口**，实际逻辑已迁移到 `src/hdzz/` 模块：

| 文件 | 作用 |
|------|------|
| `ag_wmc_watch.py` | 调用 `src/hdzz/core/watcher/ag_watcher.py` |
| `follow_engine.py` | 调用 `src/hdzz/core/follower/engine.py` |
| `member_arsenal_watch.py` | 调用 `src/hdzz/core/member/keeper.py` |
| `webui_server.py` | 调用 `src/hdzz/api/webui/server.py` |
| `telegram_bot.py` | 调用 `src/hdzz/api/telegram/bot.py` |
| `settlement_importer.py` | 调用 `src/hdzz/core/settlement/importer.py` |

#### 📌 辅助模块

| 文件 | 作用 |
|------|------|
| `member_client.py` | 会员端 HTTP 客户端封装（登录、下注、查询接口） |
| `member_follow_bet.py` | 跟单下注的核心逻辑（盘口匹配、参数转换） |
| `playwright_proxy.py` | Playwright 浏览器代理配置工具 |
| `tg_status_log.py` | Telegram 状态推送工具（支持 IP 地理位置查询） |
| `odds_quote_watch.py` | 赔率监控模块（实时跟踪盘口变化） |

#### 📌 工具脚本 (`app/tools/`)

| 文件 | 作用 |
|------|------|
| `capture_hga027_endpoints.py` | 抓取 hga027 域名的 API 端点（用于域名切换） |
| `switch_member_base_url.py` | 批量切换会员账号的域名 |
| `diag_game_more_line_mapping.py` | 诊断盘口线映射问题 |
| `package_portable.ps1` | 打包便携式版本（Windows） |

#### 📌 前端界面 (`app/webui/`)

| 文件 | 作用 |
|------|------|
| `index.html` | Web 管理界面主页（单页应用） |
| `app.js` | 前端逻辑（注单展示、账号管理、跟单配置） |
| `style.css` | 暗色主题样式 |

#### 📌 运行时目录

| 目录 | 作用 |
|------|------|
| `app/.run/` | 进程 PID 文件、日志文件 |
| `app/data/` | 运行时数据（账号信息、跟单配置、缓存） |

### 2️⃣ `src/hdzz/` - 重构后的模块化代码

这是**新架构的核心**，采用清晰的分层设计，代码更易维护和测试。

```
src/hdzz/
├── common/          # 公共工具模块
├── core/            # 核心业务逻辑
│   ├── watcher/     # 注单监听
│   ├── follower/    # 跟单引擎
│   ├── member/      # 会员账号管理
│   └── settlement/  # 结算数据处理
├── api/             # 外部接口
│   ├── webui/       # Web 界面服务
│   └── telegram/    # Telegram 机器人
└── tools/           # 命令行工具
```

#### 📌 `common/` - 公共工具层

| 文件 | 作用 |
|------|------|
| `config.py` | 配置文件读写（JSON 操作、原子写入） |
| `logger.py` | 日志管理（统一日志格式、文件输出） |
| `http.py` | HTTP 客户端封装（超时控制、重试机制） |
| `parse.py` | 数据解析工具（XML、Cookie、盘口参数） |

#### 📌 `core/watcher/` - 注单监听模块

| 文件 | 作用 |
|------|------|
| `ag_watcher.py` | 后台注单监听核心逻辑（轮询 API、解析注单、写入文件） |

**核心功能**：
- 通过 `transform.php` 接口获取后台新注单
- 支持多账号并发监听
- 自动处理掉线重连
- 使用 Playwright 处理需要浏览器的登录场景

#### 📌 `core/follower/` - 跟单引擎模块

| 文件 | 作用 |
|------|------|
| `engine.py` | 跟单引擎主逻辑（读取注单、匹配规则、调度下注） |
| `executor.py` | 下注执行器（会员端 API 调用、会话管理） |
| `strategy.py` | 跟单策略（盘口线转换、金额计算、分单逻辑） |
| `models.py` | 数据模型（`BetParams`、`RetryJob` 等） |

**核心功能**：
- 实时读取 `orders/` 目录的新注单
- 根据 `follow_settings.json` 匹配跟单规则
- 支持固定金额、比例跟单、封顶限制
- 支持分单（一笔订单拆成多笔下注）
- 智能重试机制（封盘等待、盘口线查找）
- 记录跟单结果到 `follow_results.jsonl`

#### 📌 `core/member/` - 会员账号管理模块

| 文件 | 作用 |
|------|------|
| `keeper.py` | 会员账号守护进程（自动登录、会话保活、cookie 刷新） |

**核心功能**：
- 读取 `arsenal.json` 中的会员账号
- 自动登录会员端（支持验证码手动处理）
- 定期检测会话有效性，掉线自动重登
- 更新 `uid`、`mid`、`cookie` 等关键参数

#### 📌 `core/settlement/` - 结算数据模块

| 文件 | 作用 |
|------|------|
| `importer.py` | 从后台抓取历史结算数据（用于盈亏统计） |

#### 📌 `api/webui/` - Web 界面服务

| 文件 | 作用 |
|------|------|
| `server.py` | HTTP 服务器（提供 RESTful API 和静态文件服务） |

**提供的 API 端点**：
- `/api/orders` - 获取注单列表
- `/api/targets` - 管理后台账号
- `/api/arsenal` - 管理会员账号
- `/api/follow_settings` - 跟单规则配置
- `/api/diagnostics` - 系统诊断信息
- `/api/start_core` / `/api/stop_core` - 启动/停止核心服务

#### 📌 `api/telegram/` - Telegram 机器人

| 文件 | 作用 |
|------|------|
| `bot.py` | Telegram Bot 逻辑（命令处理、消息推送） |

**支持的功能**：
- 查看实时注单
- 查看跟单结果
- 管理后台账号和会员账号
- 远程启动/停止服务
- 接收系统通知（新注单、跟单成功/失败）

## 🔄 系统工作流程

### 1. 启动流程

```
用户双击启动脚本
    ↓
app.py 启动
    ↓
启动 4 个子进程：
    ├─ ag_wmc_watch.py      (监听后台注单)
    ├─ member_arsenal_watch.py  (维护会员会话)
    ├─ follow_engine.py     (执行跟单下注)
    └─ webui_server.py      (提供 Web 界面)
```

### 2. 注单监听流程

```
ag_wmc_watch.py
    ↓
每 N 秒轮询 transform.php
    ↓
解析新注单（赛事、盘口、金额）
    ↓
写入 orders/<target>.jsonl
    ↓
(可选) 推送到 Telegram
```

### 3. 跟单执行流程

```
follow_engine.py
    ↓
监听 orders/ 目录新文件
    ↓
读取新注单
    ↓
匹配 follow_settings.json 规则
    ↓
计算跟单金额（固定/比例/封顶）
    ↓
从 arsenal.json 选择会员账号
    ↓
调用会员端 FT_bet API 下注
    ↓
记录结果到 follow_results.jsonl
    ↓
(可选) 推送到 Telegram
```

### 4. 会员会话维护流程

```
member_arsenal_watch.py
    ↓
读取 arsenal.json
    ↓
每 N 秒检测会话有效性
    ↓
如果掉线：
    ├─ 使用 Playwright 自动登录
    ├─ 提取新的 uid/cookie
    └─ 更新 arsenal.json
```

## 🎨 架构设计特点

### ✅ 优点

1. **进程隔离**：各功能模块独立进程，互不影响，单个模块崩溃不影响整体
2. **热加载配置**：修改 `config.json` 无需重启，监听脚本自动加载新配置
3. **文件通信**：通过 JSONL 文件传递注单数据，简单可靠，易于调试
4. **便携式打包**：支持打包成无需安装的独立应用
5. **模块化重构**：新代码（`src/hdzz/`）采用清晰的分层架构，易于维护

### 🔧 技术亮点

1. **原子写入**：使用临时文件 + `replace()` 保证 JSON 文件不会写坏
2. **智能重试**：封盘等待、盘口线查找等场景的智能重试机制
3. **分单策略**：支持将一笔订单拆成多笔下注，降低风险
4. **会话复用**：尽量复用已登录会话，减少频繁登录触发风控
5. **Playwright 集成**：处理需要浏览器的复杂登录场景（验证码、图形校验）

## 🚀 快速启动指南

### macOS


```bash
cd app
```

## 📝 开发者注意事项

### 代码迁移状态

- **Legacy 文件**（`*_legacy.py`）：原始实现，功能完整但代码较长
- **新版文件**（无 `_legacy` 后缀）：轻量级 wrapper，调用 `src/hdzz/` 模块
- **推荐**：新功能开发在 `src/hdzz/` 中进行，保持模块化架构

### 日志位置

- 默认：`app/.run/logs/*.err.log`
- 可通过环境变量 `HDZZ_LOG_DIR` 自定义

### 调试技巧

1. **查看实时日志**：`tail -f app/.run/logs/*.err.log`
2. **诊断接口**：访问 `http://127.0.0.1:8080/api/diagnostics`
3. **手动测试下注**：使用 `member_follow_bet.py` 单独测试
