## 二、问题根因分析

### 2.1 LINE_NOT_FOUND 问题根因

**现象：** "盘口明明还在查水页面能看到，但跟单引擎就是找不到"

**根本原因：**

1. **bet 会员的 get_game_list 不稳定**
   - SSL EOF、连接中断、CheckEMNU 等错误频发
   - 即使有重试，仍然会导致延迟增加
   - 代码位置：`executor.py:51-110`（已有自动重试机制）

2. **严格跟原线策略过于严格**
   ```python
   # follow_settings.json
   "allow_line_change": false,              # 不允许换线
   "allow_total_line_change": false,        # 大小盘也不允许
   "wait_line_not_found_max_seconds": 30,   # 最多等待 30 秒
   ```
   **问题：** 变盘瞬间，旧盘口线消失，新盘口线出现，30 秒内如果没恢复就失败

3. **查水融合的优先级问题**
   - 虽然有 `use_quote_member_for_total_odds`，但只在**大小盘**生效
   - **让球盘**仍然依赖 bet 会员的 get_game_list
   - 代码位置：`engine.py:3288-3292`

4. **分单延迟导致盘口过期**
   - 默认 `split_delay_seconds: 8.0` 太长
   - 第 1 单成功后，等 8 秒才打第 2 单，此时盘口可能已变
   - 代码位置：`follow_settings.json:28`

**已有的缓解措施（但不够彻底）：**


### 2.2 查水融合的设计缺陷

**当前设计：**
```
┌─────────────────────────────────────────────────────┐
│            当前查水融合架构（部分生效）                │
└─────────────────────────────────────────────────────┘

1. 跟单来单
   ↓
2. 使用 bet 会员
   ↓
3. ❌ get_game_list（不稳定）
   ↓
   如果失败/超时 → 进入 LINE_NOT_FOUND 探测窗口
   ↓
4. ✅ 大小盘：尝试从 quote 会员/缓存取值
   ❌ 让球盘：仍然依赖 bet 会员
   ↓
5. FT_bet 下注
```

**核心问题：**

1. **quote 会员的优先级不够高**
   - 应该让 quote 会员成为**首选数据源**
   - bet 会员只在 quote 失败时作为兜底

2. **缓存 TTL 过短**
   - XML 缓存只有 0.8 秒，分单时基本失效
   - Quote 缓存 2.5 秒，勉强够用但不够稳

3. **让球盘没有享受到查水融合的红利**
   - 只有大小盘用 `use_quote_member_for_total_odds`
   - 让球盘的失败率可能更高

#### 优化 3：添加"快速诊断"工具

**目标：** 帮助用户快速定位问题

**实现方式：** 创建 Python 诊断脚本

```python
# app/tools/diagnose_follow.py（新建）
#!/usr/bin/env python3
"""
跟单配置诊断工具
"""
import json
from pathlib import Path

def diagnose_settings():
    """诊断 follow_settings.json 配置"""
    settings_path = Path("app/data/follow_settings.json")
    settings = json.loads(settings_path.read_text())

    issues = []
    warnings = []

    # 检查 1：分单延迟是否过长
    if settings.get("split_delay_seconds", 0) > 2.0:
        issues.append(
            "❌ split_delay_seconds={} 过长，建议改为 0.3-1.0"
            .format(settings["split_delay_seconds"])
        )

    # 检查 2：分单数量是否过多
    if settings.get("split_count", 0) > 4:
        warnings.append(
            "⚠️ split_count={} 可能导致没跟全，建议滚球改为 2-3"
            .format(settings["split_count"])
        )

    # 检查 3：查水融合是否开启
    if not settings.get("use_quote_member_for_total_odds"):
        issues.append("❌ use_quote_member_for_total_odds 未开启")

    # 检查 4：缓存 TTL 是否过短
    if settings.get("odds_cache_max_age_seconds", 0) < 2.0:
        warnings.append(
            "⚠️ odds_cache_max_age_seconds={} 过短，建议 3-4 秒"
            .format(settings["odds_cache_max_age_seconds"])
        )

    # 检查 5：是否有查水账号
    quote_path = Path("app/data/quote_member.json")
    if not quote_path.exists():
        issues.append("❌ 未配置查水账号（quote_member.json）")

    # 输出诊断结果
    print("=" * 60)
    print("📊 跟单配置诊断结果")
    print("=" * 60)

    if issues:
        print("\n🚨 严重问题（必须修复）：")
        for issue in issues:
            print(f"  {issue}")

    if warnings:
        print("\n⚠️ 优化建议：")
        for warning in warnings:
            print(f"  {warning}")

    if not issues and not warnings:
        print("\n✅ 配置正常，无明显问题")

    print("\n" + "=" * 60)

if __name__ == "__main__":
    diagnose_settings()
```

#### 规划 2：动态分单策略

**目标：** 根据盘口稳定性动态调整分单数量和延迟

**实现思路：**

```python
# src/hdzz/core/follower/dynamic_split.py（新增）

def calculate_dynamic_split(order, market_volatility):
    """
    根据盘口波动性动态调整分单策略

    Args:
        order: 订单信息
        market_volatility: 盘口波动性（0-1，越大越不稳定）

    Returns:
        (split_count, split_delay_seconds)
    """
    # 滚球 + 高波动 → 分单少 + 延迟短
    if order.is_live and market_volatility > 0.7:
        return (2, 0.3)

    # 滚球 + 低波动 → 正常分单
    if order.is_live:
        return (3, 0.5)

    # 早盘 + 大额 → 多分单
    if order.amount > 50000:
        return (5, 1.0)

    # 默认
    return (3, 0.5)
```

```python
# engine.py（主循环）

    # 覆盖配置
    order.split_count = split_count
    order.split_delay_seconds = split_delay
```

### 5.3 如何排查常见问题

#### 问题 1：LINE_NOT_FOUND 频繁出现

**症状：**
```
目标盘口线暂时找不到（让球 0.5/0 → 0.5），正在重试 err=LINE_NOT_FOUND
```

**排查步骤：**

1. **检查查水账号是否在线**
   ```bash
   # 查看 quote_member.json
   cat app/data/quote_member.json

   # 查看 arsenal.json 中对应账号的状态
   cat app/data/arsenal.json | jq '.members[] | select(.role == "quote")'
   ```

2. **检查配置是否正确**
   ```bash
   cat app/data/follow_settings.json | jq '{
     use_quote_member_for_total_odds,
     game_more_scan_all_gids,
     wait_line_not_found_max_seconds,
     split_delay_seconds
   }'
   ```

3. **在查水页面手动查询**
   - 打开 `http://localhost:8000/chashui/index.html`
   - 输入出问题的 gid
   - 查看是否能找到盘口

4. **应用优化配置**（见 4.1 节）

---

#### 问题 2：分单总是没跟全

**症状：**
```
跟单失败(不重试) split=2/5 order=123456
```

**排查步骤：**

1. **检查分单配置**
   ```bash
   cat app/data/follow_settings.json | jq '{
     split_count,
     split_delay_seconds
   }'
   ```

2. **计算总耗时**
   ```
   总耗时 = split_count * split_delay_seconds
   例如：5 * 8.0 = 40 秒
   ```
   如果 > 30 秒，盘口很可能已变

3. **优化方案：**
   - 降低 `split_count`：5 → 3
   - 缩短 `split_delay_seconds`：8.0 → 0.5
   - 总耗时：3 * 0.5 = 1.5 秒 ✅

---

#### 问题 3：查水账号频繁掉线

**症状：**
```
会员登录失效（1X014），正在更换会员重试。
```

**排查步骤：**

1. **检查 cookie 是否过期**
   - cookie 有效期通常 1-7 天
   - 需要手动更新

2. **检查是否有重复登录**
   - 查水账号和下注账号不能是同一个
   - 多个进程不能共用同一个账号

3. **检查代理是否稳定**
   ```bash
   curl -x http://127.0.0.1:7897 https://ag.hga039.com -I
   ```

4. **解决方案：**
   - 使用 WebUI 的"检测/重登"功能
   - 或手动更新 cookie

---

#### 问题 4：WebUI 打不开 / 查水页面空白

**排查步骤：**

1. **检查 webui_server 是否运行**
   ```bash
   ps aux | grep webui_server.py
   ```

2. **检查端口是否被占用**
   ```bash
   lsof -i :8000
   ```

3. **查看 webui 日志**
   ```bash
   tail -f app/.run/logs/webui_server.log
   ```

4. **重启 webui_server**
   ```bash
   pkill -f webui_server.py
   cd /Users/zsc5200x/Desktop/杰尼龟共享文件夹/hdzz
   nohup python3 app/webui_server.py > app/.run/logs/webui_server.log 2>&1 &
   ```
